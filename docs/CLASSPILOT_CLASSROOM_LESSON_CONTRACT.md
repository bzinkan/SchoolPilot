# Reviewed Classroom lesson prerequisites

This implementation candidate adds server-owned preconditions to existing commands. It adds no extension command fields, capability, tenant table or product flag. SchoolPilot API/web deployment and the separately packaged ClassPilot extension retain their release boundaries.

`POST /api/classpilot/flight-paths/from-classroom` accepts optional `reuseReviewedSource: true`. Canonical normalization happens first. The transaction locks the school/staff lifecycle and serializes the exact tenant, actor, course, selected resource IDs and canonical policy. It reuses only an actor-owned private, non-official Google Classroom source with identical allowed domains/resources and an empty block list. An explicit legacy import with the option omitted still creates a new personal Flight Path. Reviewed reuse returns `reused` and the Flight Path's public `updatedAt`.

`apply-flight-path` accepts optional `expectedFlightPathUpdatedAt`, a strict ISO instant. Under the canonical command issuance locks, the server locks the same-school currently applicable Flight Path row, compares its actual content timestamp at public JavaScript Date millisecond precision, and materializes the policy from that locked row. A changed review receives `409 FLIGHT_PATH_REVIEW_STALE` before any command commits. The additive `flightPathContentRevisionMigration` installs `flight_paths.updated_at` and a SECURITY INVOKER trigger that owns a monotonic millisecond value for every meaningful row mutation, including writes from older compatible application images. No-op updates preserve the value, and caller-supplied timestamps cannot defeat the fence. Keep this additive column and trigger on rollback.

`GET /api/classpilot/commands/:id/status` requires exactly one current teaching session or supervision context authority, the current scheduled authority revision header where applicable, and the same actor who issued the source command. It returns `{ command }` with the existing protected public command/target projection and `Cache-Control: no-store`. It does not depend on recent-history limits. Per-target completed status, the actual `result.outcome`, and server-derived Focus continuation status remain visible; device IDs, login IDs and private authority records remain excluded.

`open-tab` accepts optional `afterRestrictionCommandId`. This option requires explicit selected student recipients. For each recipient, the canonical issuance transaction proves a same-school, same-actor, same-session/context `apply-flight-path` source; a completed/applied source target; the same current student/login/device; the exact current desired and actually applied revision; current unexpired authority; and the scheduled ownership revision when applicable. The canonical state ACK's `classroomStateRevision` and command ACK's `appliedRevision` are both supported, with conflicting revisions refused. Pending, failed, unsupported, replaced or rebound sources mark only their recipient unavailable. The server rechecks the prerequisite immediately before exact-bound delivery and refuses a withheld full restriction snapshot. The extension's open command data remains strictly `{ url }`.

The lesson UI reviews normalized boundaries, creates/reuses that personal policy, applies with the returned timestamp pin, polls this exact command's actual per-student application receipts, and opens only confirmed recipients with the source precondition. Opening a lesson does not imply Focus. Optional Open + Focus retains its separate validated receipt continuation and child-command confirmation.

Local source/type, restricted-role database, HTTP, concurrent reuse and held-row/control-lock race tests validate the implementation candidate. Combined CI, packaged extension acceptance where applicable, managed devices and operator deployment evidence remain separate review/release gates. No production deployment or Store upload is performed by this contract.

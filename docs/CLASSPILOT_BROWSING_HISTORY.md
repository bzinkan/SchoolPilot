# Student browsing history

The Student Detail drawer's History tab queries the server by student and school-local date range. It loads materialized top domains by day and a separate observation list, with 100 entries per page and a hard server cap of 500. The default list shows observations with page details; an option includes observations without page details. Changing dates, students or that option cancels stale requests and restarts pagination. The UI distinguishes empty observations, expired dates, denied access, unavailable service and failed requests.

When an observation has no page title (including stored `Unknown` placeholders), the web app derives a display label from its recorded URL: for example, `Google search: photosynthesis`, `Google Docs document`, or the website hostname. Reported page titles take precedence. If neither a usable title nor a recognizable URL is available, it shows `Page details unavailable`. These labels also apply to recent activity, the browsing timeline and student tiles. They describe the recorded page, never infer typing, editing, video playback or a cause for missing data, and do not change stored observations or off-task classification.

`GET /api/classpilot/students/:studentId/browsing-history` accepts `startDate`, `endDate` (inclusive local dates, maximum 366 days), `limit`, `view=pages|all` and an opaque `cursor`. The API defaults to `all` for compatibility; the drawer requests `pages` by default. Omitted dates select today in the school's timezone. The response includes the selected view, timezone, retention cutoff, partial-expiry flag, scope, observation timestamps, page URL/title, educational classification, nullable stored content category, lock/camera indicators and estimated seconds. It contains no device IDs. `/browsing-history/domains` returns existing daily materializations for administrators and authorized class-session usage for teachers. Missing materializations are unavailable, not proof of no browsing; supervision-only summaries remain partial and the raw list remains authoritative for those observations.

The `pages` view filters before the page limit, so a run of hundreds of heartbeat observations without page details cannot consume result pages. An observation has page details when it contains a nonblank URL (including an internal browser URL) or a nonblank title other than the case-insensitive placeholders `Unknown`, `Page details unavailable`, `No page details` and `Browser observation`. Whitespace around titles is ignored. Meaningful title-only observations such as `Signing in` and `Assigned page` remain visible. The `all` view retains every authorized observation, including lock/camera evidence without page details. These are presentation filters: heartbeat storage, monitoring, retention and domain materializations remain unchanged, and missing page details are never filled with an earlier URL or treated as proof of an offline Chromebook.

Deploy the API before the web client so `view=pages` is supported when the drawer begins requesting it. This change requires no data migration or Chrome extension release and applies to already-retained history.

Date boundaries use the canonical `schools.school_timezone`, the same clock as ClassPilot classes, dashboard and Clever sync. The legacy `settings.school_timezone` field does not override history dates; `settings.retention_hours` still supplies the retention policy.

Administrators may inspect all retained observations for the student. Teacher authority comes from completed frozen staff and roster snapshots on live teaching sessions and retained report authority, using the same helpers as Student Data. Current group assignment alone, an unattended scheduled report, or an administrator's Observe access cannot grant teacher history. The interval ends at the earliest actual/session/report deadline, scheduled end, twelve-hour limit or present time, and starts no earlier than roster capture. Delegated supervision is subtracted from class access; a teacher receives only their own supervision intervals, bounded by assignment/release/context times. Raw reads are clipped to the current school retention cutoff on every page.

Pagination seeks by `(timestamp DESC, id DESC)` with timestamp precision retained to six fractional digits. The cursor is bound to actor, role, school, student, date range and view and retains a fixed request horizon. Existing cursors remain usable in the `all` view; switching views requires a fresh first page. Each page rechecks authority and retention. Concurrent newer observations do not shift subsequent pages. Changing membership, retention or dates never makes a prior cursor an authority token.

Whole-session domain summaries are released only when an authorized interval covers the full materialized session/day slice. Late roster or staff capture, delegated gaps, clipped retention, timezone changes and unfinished session windows withhold that aggregate and mark the summary partial or unavailable. Aggregated domains cannot be made safe by merely trimming their displayed timestamps. A cursor also carries its original local date range so paging today's history continues safely across school midnight.

Estimated durations use the next raw observation for the same student and device inside the same authorized interval, only when observations are no more than 60 seconds apart. The next observation lookup includes rows hidden by the `pages` view, so missing-page intervals are never credited to the previous known page. Equal timestamps, isolated observations, gaps and the final observation contribute zero. They do not claim exact dwell time or fill unseen intervals. Category labels do not themselves make an observation off-task; historical null categories remain null.

## Query-plan evidence

The measurements below cover the original `all` view. They do not measure the `pages` predicate; long missing-detail streaks require scanning past those rows within the authorized student/date range.

Read-only inspection of the local development table (115 rows) used a sequential scan with a small sort, 0.652 ms. That fixture was too small to justify a production index decision. `scripts/verify-browsing-history-plan.ts` creates connection-local synthetic temporary data (500,000 heartbeats, 100 students and multiple devices) and compares a representative deep timestamp/id cursor query. It never changes application records.

With the existing `(student_id, timestamp)` index, PostgreSQL scanned 102 rows, performed an incremental sort and returned 101 rows in 0.314 ms, reading 105 local blocks. A proposed `(school_id, student_id, timestamp DESC, id DESC)` index scanned 101 rows in 0.318 ms with the same block count. These local runs show no meaningful improvement from the proposed index, so this feature retains the existing indexes. The existing school/device/student/timestamp index supplies the per-row next-observation lookup. These are development query-plan observations, not production latency or scale guarantees.

Run `node --env-file-if-exists=.env --import tsx scripts/verify-browsing-history-plan.ts` for the bounded synthetic comparison. The script refuses non-local database hosts. Unit tests in `tests/classpilot-browsing-history.test.ts` cover school-local DST dates, interval subtraction, cursor precision/scope and duration boundaries. The integration suite covers pagination, retention, cross-school denial and frozen teacher/supervision authorization.

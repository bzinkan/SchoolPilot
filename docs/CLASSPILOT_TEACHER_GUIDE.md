# ClassPilot Teacher Guide

> Generated from the structured in-app ClassPilot guide source. Do not edit this file by hand.

Prepare, start, guide, monitor, and wrap up an exact-authority ClassPilot class.

**Route:** /classpilot/my-settings/guide

## Prepare



### Prepare your class

**Who can use this:** Teacher or administrator

Check the roster, choose a class, and set up the tools you expect to use before the bell.

1. **Review your assigned classes.** Confirm the class and students you expect to teach. Ask an administrator to correct official class membership or teacher assignments.
2. **Build reusable tools.** Create personal Flight Paths, Block Lists, and subgroups in My Settings. Flight Paths allow only their listed destinations; Block Lists deny their listed domains.
3. **Choose classroom defaults.** Set your preferred tab limit and default Flight Path. School policy can be stricter than a personal preference.
4. **Check today’s schedule.** If your school permits one-day schedule changes, review requests and approved changes before class begins.

> **Flight note:** Use clear names such as “Period 2 Research” so the right tool is easy to find during class.

### Request a one-day schedule change

**Who can use this:** Primary teacher; school policy may require approval

Exchange the scheduled time of an eligible class for one instructional day without changing teachers or rosters.

1. **Start a request.** Choose an eligible class pair and instructional date, then review the normal and proposed times.
2. **Add context.** Enter a reason when required by school policy and send the request to the other primary teacher.
3. **Track the decision.** Use Needs Action, Upcoming, and History. A request changes nothing until every required acceptance and approval is complete.

> **Check before continuing:** A same-day change cannot begin after either affected class has already started.

## Start



### Start, resync, skip, or end class

**Who can use this:** Assigned class teacher

Use the class controls deliberately so monitoring and student controls follow the correct teaching session.

1. **Follow the scheduled Class.** When scheduled Class mode is enabled, your Dashboard automatically shows the current class or testing assignment and its students, including offline students. Applied profiles and approved schedule changes determine the next class. No click is needed at the handoff.
2. **Browse between handoffs.** You may open Claimed, Available or Observe between assignments. The next scheduled handoff returns you to Class. Refreshing the same assignment does not change your chosen view. Starting testing and Updating class mean the server has not confirmed the new assignment yet.
3. **Select an unscheduled class.** Choose the class you are teaching when you need a manual session. Scheduled classes can start only inside their effective window.
4. **Start the session.** Start class and wait for the roster and connection states to settle before sending controls.
5. **Resync when needed.** Use Resync if the roster or current session appears out of date. Resync refreshes authority; it does not broaden your class access.
6. **Skip or end intentionally.** Skip Today prevents the scheduled occurrence from starting. End Class closes the current session and begins wrap-up processing.

> **Flight note:** If the wrong class is active, end it before starting another one; do not try to control students from a stale class view.

### Read Dashboard status correctly

**Who can use this:** Teacher or administrator

Connection freshness, previews, and sign-in state are separate signals.

1. **Use the counters.** Online and Idle students have current heartbeat coverage. Signed-out students have no active ClassPilot student session and show Waiting for ClassPilot sign-in. They stay in the roster, and preview requests resume automatically when they sign in. Signal Lost means a signed-in browser has stopped reporting; the cause is not assumed.
2. **Treat previews as passive evidence.** A screen preview is an authorized still image with its own age. It does not determine whether a student is connected and it never replaces heartbeat status.
3. **Recognize transitions.** Signing in means an approved identity-provider flow is active. Updating preview means a new control revision is waiting for its matching still image. Neither label means the student is stale.
4. **Wait for exact authority.** When a student changes device or session, ClassPilot clears prior-session details before showing the new binding.
5. **Check an access warning.** Students waiting to sign in do not trigger a live-preview access warning. If a preview or history access warning remains, use Refresh class to check the current class access again. That action does not sign students in.

> **Check before continuing:** Do not interpret a recent preview as proof that commands are currently available. Use the connection label and command outcome.

## Guide



### Target exact students and read results

**Who can use this:** Assigned or coverage teacher

ClassPilot never turns a missing target into a class-wide action.

1. **Choose the scope.** Use student checkboxes, Select All, or a subgroup. Recheck the selected count before confirming the action.
2. **Send the command.** ClassPilot resolves the exact students and their current sessions. It does not substitute another device or student when a target is missing.
3. **Read every outcome.** Applied is enforced now. Pending is waiting for an eligible connection. Unavailable means the action cannot safely reach that student, such as when an extension update is required.
4. **Follow up narrowly.** Retry only the students who need it after their status changes. A partial result is not a reason to resend to the whole class.

> **Flight note:** The result summary can contain both pending and unavailable students; review both counts.

### Open a URL and manage tabs

**Who can use this:** Assigned or coverage teacher

Send learning resources and close the exact tabs shown for a student.

1. **Open a resource.** Select the intended students, choose Open URL, and verify the address before sending.
2. **Inspect current tabs.** Use Manage Tabs to review the current tab inventory for each selected student.
3. **Close exact rows.** Choose the specific tab rows to close, or use Close All when that is truly intended. Duplicate addresses remain separate tabs.
4. **Use tab limits carefully.** A tab limit manages tab count but preserves the last usable destination and an active school-approved sign-in flow.

### Use Waypoints and Flight Paths

**Who can use this:** Assigned or coverage teacher

A Waypoint holds students on one destination site; a Flight Path confines browsing to a prepared set of destinations.

1. **Choose the restriction.** Use a Waypoint to hold students on one destination site (the whole site is allowed) or apply a Flight Path for a bounded set of learning destinations.
2. **Account for signed-out students.** A saved destination can wait for eligible signed-out students. A Current Page Waypoint cannot resolve a signed-out student’s page, so those students are skipped and counted.
3. **Start from the Student Portal.** When the school enables the Student Portal, students signing into ClassPilot with an active restriction start at the school’s selected portal, such as Clever. They choose a teacher-approved destination there. Finishing provider sign-in does not automatically open a learning site, and other sites remain blocked.
4. **Allow school-approved sign-in.** If a chosen destination needs an approved provider such as Clever or Google Accounts, the student can complete that sign-in while the Waypoint or Flight Path remains active. An identity-provider callback does not trigger an automatic jump to a learning site.
5. **Remove the right control.** Unlock removes a Waypoint screen lock without silently deleting an active Flight Path. Remove Flight Path is a separate action.

> **Check before continuing:** The portal remains available while the restriction is active. An identity-provider page is for sign-in, not proof that the student reached the assigned learning destination.

### Use focus and communication tools

**Who can use this:** Assigned class teacher; coverage has a smaller tool set

Apply the least disruptive classroom tool that solves the moment.

1. **Block a defined set.** Apply or remove one of your saved Block Lists. School and teacher blocks remain authoritative during sign-in.
2. **Use Attention briefly.** Attention takes precedence over every browsing exception. Turn it off as soon as the class is ready to continue.
3. **Communicate in context.** Use teacher messages, hand raises, polls, and timers only inside the active class that owns those tools.
4. **Clear before the next sign-in.** When a restriction should not follow a student into the next session, clear it before sign-in and verify the resulting status.

### Use Class tools during a lesson

**Who can use this:** Assigned classroom teacher

Help, Messages, Activities, and Tools share one workspace. New capabilities appear as your school enables them and student extensions become ready.

1. **Open or pin the workspace.** Open Class tools at the bottom right. Its separate Help and Messages counts show waiting requests and unread conversations; an active countdown stays visible. Pin the panel to make room beside the student tiles, drag or resize it, or use Reset position. On smaller screens it becomes a drawer. Open URL, Manage Tabs, Waypoints, Flight Paths, Block Lists, and Student Sign Out remain in the Dashboard toolbar.
2. **Manage the help queue.** Help lists immediate requests oldest first. Acknowledge tells the student You’re on my list; Mark helped finishes the request. Students can edit a request without losing their place or withdraw it. Questions for later are separate: add a group label, answer, then mark answered. Requests and questions stay private to authorized staff.
3. **Keep conversations in context.** Messages keeps quick replies, Got it, delivery and Seen indicators, per-student drafts, transcripts, and readiness explanations. A tile’s unread badge opens that student. Switching tools preserves your draft without marking incoming messages read. Pause stops new student messages while allowing your replies; turning messaging off has stronger restrictions. Clear thread and End chat for student remain separate actions. A real classroom or account change clears outgoing drafts.
4. **Publish and review an activity.** In Activities, start a lesson with pinned directions, resource links, and optional checklist items. Students explicitly choose Working, Stuck, Ready for review, or Finished. No response means Not reported. Checking an item does not change status, and Stuck does not raise a help request. Edits preserve completion only for unchanged checklist items; a new activity resets progress.
5. **Check understanding and follow up.** Choose a quick poll or prepare a multiple-choice or short-text exit ticket. Only one response prompt is active at a time. Send and close it deliberately; text responses are limited to 500 characters and the first submission is retained. A response or work-status group lets you preview the exact students before sending a message or resource. Review reached, unavailable, unsupported, and pending outcomes separately.
6. **Use time, attention, and participation.** Tools offers Pause, Resume, +1 minute, and Stop for a supported timer, plus Eyes up and Release attention. A timer is limited to 60 minutes remaining. Participation skips marked-absent and excluded students, avoids repeats until New round, and allows Pass. Ask for volunteers uses a separate Yes/Pass question; help requests are never volunteers.
7. **Present and reuse deliberately.** Open presentation view for instructions, the timer, and aggregate choice results without names, private messages, help details, or text responses. My templates are private to you in this school. Routines publish directions, open resources, apply a saved Flight Path, start a timer, and prepare prompts. Advance every step yourself; a timer finishing never advances a routine. Retry eligible unsuccessful students keeps original recipients and does not repeat successful deliveries. History follows your school’s retention policy.

> **Flight note:** Changing the Dashboard selection affects new actions. Existing timers, activities, and prompts keep their original recipients.

> **Flight note:** An unsupported outcome means the student needs compatible extension support. Existing classroom and messaging tools remain available according to school policy.

## Monitor



### Use the student drawer responsibly

**Who can use this:** Authorized teacher or administrator

Review current context and authorized history without treating one signal as the whole story.

1. **Open the exact student.** Select a student tile to see current context, browsing history, and the passive preview authorized for this class.
2. **Check time and context.** Review timestamps, class ownership, attendance or pass context, and status before drawing a conclusion from a title or domain.
3. **Use educational purpose.** Monitor only for legitimate instruction, safety, and support. Follow school policy for documentation or escalation.
4. **Close when finished.** Exit the drawer when the focused review is complete so the normal class view remains clear.

> **Check before continuing:** A page title, category, or still image can be incomplete. Confirm context before intervening.

### Work a temporary supervision session

**Who can use this:** Staff member with a Coverage assignment

Claim only assigned students, use the coverage tool set, and release them when supervision ends.

1. **Distinguish setup, permission and activity.** In Supervision, Live now shows current sessions, Scheduled shows your own or assigned dated testing and coverage, and Saved groups holds reusable rosters you may access. A saved roster and Authorized staff permission do not start supervision. A student in a saved testing group is part of testing only during an actual testing session.
2. **Review a temporary session.** Start session reviews the exact participants, supervising staff, purpose and end time before starting. The default purpose is Supervision. Group names do not choose Testing automatically. Scheduled starts with today in the school’s timezone and includes actual applied testing blocks and existing dated coverage records, not unapplied saved profiles. School administrators schedule testing dates.
3. **Follow your supervision.** When scheduled Class mode is enabled, scheduled testing and scheduled-class coverage appear in Class with the same classroom tools supported by the Chromebook extension. Direct pickups, manual Other sessions and manually started supervision groups appear in Claimed. An explicit ad hoc claim opens Claimed; the next scheduled handoff returns to Class. Schools awaiting this rollout retain the existing combined supervision view.
4. **Read the dashboard counts.** In scheduled Class mode, Claimed counts your ad hoc students, including offline students; scheduled testing is counted in Class. When the Coverage button is available, its number counts active supervision sessions visible to you. One ad hoc session with 20 students can show Claimed 20 and Coverage 1. Counts refresh while you view Class, and ended assignments stop contributing. An em dash (—) means the count is unavailable; use Retry supervision refresh if an error appears.
5. **Filter Available or Claimed students.** Combine Class, Grade, and student search to find the students you need. Class refers to official roster membership, not the class currently meeting. Clear filters restores the list. Filtering does not change rosters, assignments, or permissions. Select all matching students selects the students matching those filters; check the selected count before acting.
6. **Open Available.** Review students made available to your supervision group and claim only the assignment you are taking.
7. **Confirm Claimed.** Wait for the claimed context to load before sending an action. The class owner and exact student bindings remain authoritative.
8. **Use coverage controls.** Send resources, manage allowed tabs and restrictions, message students, or apply the controls shown in Coverage. Tools not shown are not part of Coverage authority.
9. **Release cleanly, including offline students.** Release an individual student or select several and use Release selected, then confirm the reason. Offline students can be selected and released even when browser commands are unavailable. Release ends their assignment and reportable supervision time immediately; their Chromebook receives the resulting state when it reconnects. Releasing the last student ends the supervision context so the dashboard can return to the current scheduled class.
10. **Finish scheduled testing.** Testing ends automatically at its assigned end time and students follow their next class. To finish early, use End testing and confirm the named assignment. This releases that testing assignment without ending an underlying regular class. If no class follows for you, the Dashboard shows an idle state. Extension update required means that Chromebook cannot yet perform the selected tool.
11. **Review your activity summary.** When your testing or Coverage assignment ends, an email summarizes the students and time intervals you actually supervised. A handoff gives each staff member a separate summary. Late arrivals, early releases and returning students are limited to their actual supervision intervals. An extension keeps the same assignment open; releasing only some students does not send another email.

> **Flight note:** Allow at least 30 seconds after supervision ends for final observations to settle, plus normal processing and email delivery time. Missing or unavailable observations do not establish that a student stayed on task. Your school may configure a central recipient to receive a copy.

## Wrap Up



### Wrap up and troubleshoot

**Who can use this:** Teacher or administrator

End the session, review outcomes, and know when an administrator must help.

1. **Check temporary controls.** Ending class clears Waypoints, Flight Paths, and other session controls automatically. Lift anything sooner only if students need it before the bell, then end class and wait for the session to close.
2. **Review the summary.** Check the session summary and any pending or unavailable outcomes that need later follow-up.
3. **Retry connection issues once.** Resync the class after a student reconnects. Do not repeatedly broadcast a command while the student remains unavailable.
4. **Escalate policy issues.** Ask an administrator for help with extension versions, school blocks, managed configuration, provider policy, setup keys, or official roster and schedule changes.

> **Flight note:** Include the student’s displayed status, the action, and the approximate time when reporting a problem. Do not send passwords or sign-in URLs.

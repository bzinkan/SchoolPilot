# Windows browser companion integration

This additive implementation starts from reviewed SchoolPilot main `08102f9ad0bbd226a09b31b95a7cfe246977166c` and ClassPilot main `335123c8ff407446c5618e17a0c96ca94c82d157` (extension 3.0.3). Windows extension packages use a separate version and browser identities. The Chromebook release and legacy single-browser endpoints remain independent. The sibling ClassPilotDesktop repository contains the native Agent, per-user Guard, native messaging Host, signed-package tooling and canonical MVP/protocol.

## Activation and readiness

`CLASSPILOT_WINDOWS_BROWSER_MODE=on` plus a valid explicit `CLASSPILOT_WINDOWS_BROWSER_SCHOOL_IDS` CSV are both required. Missing, malformed or other configuration values disable Windows pairing and collection. Desktop visibility still independently requires `CLASSPILOT_NATIVE_VISIBILITY_MODE=on` and its own school allowlist. Neither flag is activated by this change. Local synthetic activation does not authorize production or real-student collection.

Pilot readiness is **NOT READY** until exact trusted signatures, actual managed Chrome/Edge installation and coverage, physical OS transitions, the enabled school capability matrix and integrated resource/recovery evidence are verified. Unpacked browser workers with a simulated host, SQL/RLS fixtures and synthetic lifecycle tests are independent development evidence. They do not certify signed native IPC or a managed fleet. No policy was installed on the user's always-unlocked workstation.

## Identity and transport

Authenticated administrators issue 10-minute, single-use enrollment tokens through `POST /api/classpilot/windows/enrollment-tokens`; `/enroll` returns the existing installation-purpose credential to Windows Credential Manager. `/guards` verifies the student's existing PIN with native-specific limits and issues a purpose-specific memory-only guard bearer. The guard renews every 15 seconds, expires within 45 seconds without verification and has an eight-hour absolute maximum. Reauthentication/handoff retires old bindings transactionally; another installation cannot take over implicitly. Installation revocation immediately retires guard/browser authority. Lock, sleep, sign-out, user switching and guard restart require a new PIN. Closing the capture UI keeps only the independent browser guard running; native capture must authenticate again after process restart.

The signed Host accepts only status, pair and exact-profile/epoch sign-out. It stamps Chrome versus Edge from its verified browser parent and configured exact extension origin. `/guards/pairing-proofs` issues single-use proofs lasting at most 60 seconds, bound to guard/OS-session, school, student, browser family, profile and random challenge. `/browser/pair` returns a separately hashed/revocable child credential, opaque source reference and binding revision. Browser tokens never authorize native observation or legacy browser-control endpoints; guard/native/extension credentials cannot substitute for one another. PINs and credentials do not enter diagnostics or persistent browser/native messages.

`/browser/heartbeat`, `/browser/screenshot`, `/browser/command-acks` and `/browser/action` require the child's exact source/revision. Screenshot ingestion authenticates headers before bounded JSON buffering, with a shared four-second deadline and separate bounded pre-auth/body/decoder admission. Known local invalidation fences the worker synchronously and aborts pending work. Sign-out also retires the local guard epoch; delayed replies cannot revive the old student. No offline pixel queue exists.

## Teacher model and capabilities

`POST /windows/tiles` requires explicit student IDs and exactly one authorized teaching/supervision context. It returns one projection per student, separate Chrome/Edge availability and coverage, and selected-source telemetry. Teachers see one tile with Chrome, Edge and Desktop choices. Two browser sources require an explicit initial choice. Missing/unverified coverage is visible; source loss never falls back to another browser. First-discovery authorization/service failure hides source content; only an explicit disabled/404 feature response restores the legacy route.

An ended Windows guard alone does not select a Chromebook. A later authenticated Chromebook session produces an explicit server owner marker bound to its public realtime binding. A view retaining a Windows choice offers **View Chromebook** and requires that deliberate handoff; delayed aggregates and stale clicks cannot display a previous browser binding.

`POST /windows/commands` fans permitted classroom policies across browser children and binds exact tab actions to explicitly selected opaque sources/revisions. Unsupported sources return separate unavailable outcomes. An offline student receives a persisted student-level unavailable outcome while available peers continue; this does not invent a browser identity or claim delivery to an unpaired browser. The original audience remains immutable and is reauthorized on outcome reads. Missing or stale exact tab targets never broaden the audience. `GET /windows/commands/:id` returns per-browser outcomes; a final status read expires pending policies instead of leaving indefinite pending UI. Observe is read-only.

Mixed Chromebook/Windows timer, poll and activity commands create one canonical resource and immutable audience; child browser transports share its ID. Existing validators, tool resources, chat lifecycle, hand state and poll first-answer semantics are reused under a bounded transaction scope. Separate additive activity-parent validation accepts exact same-school/same-student browser parents without inventing Chromebook device/session rows.

Capabilities are negotiated per browser and intersect school rollout flags. Browser thumbnails use the canonical class/supervision observation leases: five-second active-view cadence and 30-second background cadence, bounded by the earlier guard, classroom, school-hours or entitlement deadline. Storage, reads and decoding remain qualified by the exact browser source and binding. Desktop capture retains its separate explicit viewer grants and approximately 30-second cadence.

The reviewed baseline has no callers of the dedicated safety capture-request producer; its functioning browser safety path uses an exact ambient image. Windows implements that path and does not advertise the unused dedicated request capability. Retired Live View stays disabled. Chromebook directory-continuity and kiosk-ticket identity capabilities stay excluded because Windows replaces that bootstrap with Guard/PIN pairing. Legacy observation-only screenshot compatibility and the school-disabled read-only reporting screenshot capability are not advertised. This distinction is about actual implemented behavior, not matching every historical capability string. A school enabling additional unsupported paths must fail capability admission rather than silently receive a weaker implementation.

## Data and migration boundaries

Browser metadata uses existing school-hours/retention and historical staff access. Full-policy metadata may be observed outside a current class; student-session screenshots are immediately discarded, preserving the existing browser retention rule. Live class/supervision browser images have short exact-source TTLs. Browser events use the existing sanitizer. URL/title classification and safety processing reuse the existing services with fresh guard/policy/control checks; delayed classification is history-only unless its observation still owns the current source. Browser evidence may use only a fresh image matching that same browser source, binding, page and authority. Native Desktop pixels have no entry into any of these services.

Windows browser observations have an independent history model and browser-qualified cursors. Usage merges overlapping focused Chrome/Edge intervals, including report reads and daily totals, while preserving Chromebook-only results. Exact browser IDs correlate evidence internally; teacher-facing records expose opaque source references. Desktop images remain excluded from browser history, attendance, analytics, AI, evidence and billing.

Migrations append after the current automatic-Flight-Path/native registry history. `classpilot-windows-browser-20261028`, `classpilot-windows-history-20261028` and `classpilot-windows-activity-parents-20261029` add identity/source/command/history records and alternate activity-parent validation. The six-table `classpilotWindowsBrowserPostExpand` candidate inventory follows immutable 132 and reaches 138. Historical checksums/inventories, generic 75-table default and observed production 121-table allowlist stay unchanged. Production RLS admission remains separately authorized; changing CI's candidate inventory does not admit live production tables.

The activity-parent validators remain `SECURITY INVOKER`. Their collision checks require read-only `SELECT` access to `classpilot_windows_browsers` and `classpilot_windows_guards`, including when validating a legacy FAB record. Reviewed runtime grants for the 138-table inventory include those dependencies. Restricted test roles must grant these parent reads explicitly; neither a security-definer bypass nor a skipped Windows parent check is used. Apply the additive schema and reviewed grants before deploying the API/worker code, even while collection remains off.

## Validation and rollback

Run application build/check, test-type/cast ratchets, ordinary backend tests and forced-RLS tests serially on an isolated synthetic database. Focused Windows tests cover identity/proof purpose, single-use/replay, capabilities, exact commands/outcomes, shared tools, cross-school/student constraints, revocation and reporting. The optional real-browser bridge is invoked with `WINDOWS_BROWSER_INTEGRATION_SCRIPT` pointing to the sibling ClassPilot script; fixture secrets travel only on child stdin, never browser source or logs. An absent bridge is explicitly skipped.

Frontend validation includes the six repository-required dashboard gates, native desktop regressions, Windows source/Observe/history/expiry tests, lint and build. ClassPilot validation includes shared extension regressions, package hashes, Windows channel failure tests and actual packaged Chrome/Edge worker tests. Per-delivery validation/results and resource metrics are recorded in a separate evidence record; this document does not turn planned checks into passed claims.

Rollback disables the Windows gate/allowlist, denies new guard/proof/child work and stops current collection at the remaining lease bound. Keep additive tables, forced policies, retained browser history and cleanup jobs. Browser/guard update, uninstall and rollback require signed artifact verification and a fresh PIN; use the sibling managed-device runbook. Native visibility's rollback switch remains independent. Store submission, production activation, AWS changes and real-student collection are outside this implementation.

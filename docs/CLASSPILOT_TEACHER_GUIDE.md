# ClassPilot Teacher Guide

> Generated from the structured in-app ClassPilot guide source. Do not edit this file by hand.

Prepare, start, guide, monitor, and wrap up an exact-authority ClassPilot class.

**Route:** /classpilot/my-settings/guide

## Prepare



### Prepare your class

**Who can use this:** Teacher or administrator

Check the roster, choose a class, and set up the tools you expect to use before the bell.

1. **Review your assigned classes.** Confirm the class and students you expect to teach. Ask an administrator to correct official class membership or teacher assignments.
2. **Build reusable tools.** Create personal Flight Paths, Block Lists, and subgroups in My Settings. Flight Paths allow only their listed destinations; Block Lists deny their listed domains.
3. **Choose classroom defaults.** Set your preferred tab limit and default Flight Path. School policy can be stricter than a personal preference.
4. **Check today’s schedule.** If your school permits one-day schedule changes, review requests and approved changes before class begins.

> **Flight note:** Use clear names such as “Period 2 Research” so the right tool is easy to find during class.

[Open teaching tools](/classpilot/my-settings)

### Request a one-day schedule change

**Who can use this:** Primary teacher; school policy may require approval

Exchange the scheduled time of an eligible class for one instructional day without changing teachers or rosters.

1. **Start a request.** Choose an eligible class pair and instructional date, then review the normal and proposed times.
2. **Add context.** Enter a reason when required by school policy and send the request to the other primary teacher.
3. **Track the decision.** Use Needs Action, Upcoming, and History. A request changes nothing until every required acceptance and approval is complete.

> **Check before continuing:** A same-day change cannot begin after either affected class has already started.

## Start



### Start, resync, skip, or end class

**Who can use this:** Assigned class teacher

Use the class controls deliberately so monitoring and student controls follow the correct teaching session.

1. **Select the class.** Choose the class you are teaching. Scheduled classes can start only inside their effective window.
2. **Start the session.** Start class and wait for the roster and connection states to settle before sending controls.
3. **Resync when needed.** Use Resync if the roster or current session appears out of date. Resync refreshes authority; it does not broaden your class access.
4. **Skip or end intentionally.** Skip Today prevents the scheduled occurrence from starting. End Class closes the current session and begins wrap-up processing.

> **Flight note:** If the wrong class is active, end it before starting another one; do not try to control students from a stale class view.

### Read Dashboard status correctly

**Who can use this:** Teacher or administrator

Connection freshness, previews, and sign-in state are separate signals.

1. **Use the counters.** Online and Idle students have current heartbeat coverage. Signed-out students have no active ClassPilot student session. Signal Lost means a signed-in browser has stopped reporting; the cause is not assumed.
2. **Treat previews as passive evidence.** A screen preview is an authorized still image with its own age. It does not determine whether a student is connected and it never replaces heartbeat status.
3. **Recognize transitions.** Signing in means an approved identity-provider flow is active. Updating preview means a new control revision is waiting for its matching still image. Neither label means the student is stale.
4. **Wait for exact authority.** When a student changes device or session, ClassPilot clears prior-session details before showing the new binding.

> **Check before continuing:** Do not interpret a recent preview as proof that commands are currently available. Use the connection label and command outcome.

## Guide



### Target exact students and read results

**Who can use this:** Assigned or coverage teacher

ClassPilot never turns a missing target into a class-wide action.

1. **Choose the scope.** Use student checkboxes, Select All, or a subgroup. Recheck the selected count before confirming the action.
2. **Send the command.** ClassPilot resolves the exact students and their current sessions. It does not substitute another device or student when a target is missing.
3. **Read every outcome.** Applied is enforced now. Pending is waiting for an eligible connection. Unavailable means the action cannot safely reach that student, such as when an extension update is required.
4. **Follow up narrowly.** Retry only the students who need it after their status changes. A partial result is not a reason to resend to the whole class.

> **Flight note:** The result summary can contain both pending and unavailable students; review both counts.

### Open a URL and manage tabs

**Who can use this:** Assigned or coverage teacher

Send learning resources and close the exact tabs shown for a student.

1. **Open a resource.** Select the intended students, choose Open URL, and verify the address before sending.
2. **Inspect current tabs.** Use Manage Tabs to review the current tab inventory for each selected student.
3. **Close exact rows.** Choose the specific tab rows to close, or use Close All when that is truly intended. Duplicate addresses remain separate tabs.
4. **Use tab limits carefully.** A tab limit manages tab count but preserves the last usable destination and an active school-approved sign-in flow.

### Use Waypoints and Flight Paths

**Who can use this:** Assigned or coverage teacher

A Waypoint holds students on one destination site; a Flight Path confines browsing to a prepared set of destinations.

1. **Choose the restriction.** Use a Waypoint to hold students on one destination site (the whole site is allowed) or apply a Flight Path for a bounded set of learning destinations.
2. **Account for signed-out students.** A saved destination can wait for eligible signed-out students. A Current Page Waypoint cannot resolve a signed-out student’s page, so those students are skipped and counted.
3. **Allow school-approved sign-in.** If the destination redirects to an approved provider such as Clever or Google Accounts, the student can complete sign-in without escaping the restriction. ClassPilot shows Signing in and returns to the assigned destination afterward.
4. **Remove the right control.** Unlock removes a Waypoint screen lock without silently deleting an active Flight Path. Remove Flight Path is a separate action.

> **Check before continuing:** An identity-provider page is temporary authentication, not proof that the student reached the assigned learning destination.

### Use focus and communication tools

**Who can use this:** Assigned class teacher; coverage has a smaller tool set

Apply the least disruptive classroom tool that solves the moment.

1. **Block a defined set.** Apply or remove one of your saved Block Lists. School and teacher blocks remain authoritative during sign-in.
2. **Use Attention briefly.** Attention takes precedence over every browsing exception. Turn it off as soon as the class is ready to continue.
3. **Communicate in context.** Use teacher messages, hand raises, polls, and timers only inside the active class that owns those tools.
4. **Clear before the next sign-in.** When a restriction should not follow a student into the next session, clear it before sign-in and verify the resulting status.

## Monitor



### Use the student drawer responsibly

**Who can use this:** Authorized teacher or administrator

Review current context and authorized history without treating one signal as the whole story.

1. **Open the exact student.** Select a student tile to see current context, browsing history, and the passive preview authorized for this class.
2. **Check time and context.** Review timestamps, class ownership, attendance or pass context, and status before drawing a conclusion from a title or domain.
3. **Use educational purpose.** Monitor only for legitimate instruction, safety, and support. Follow school policy for documentation or escalation.
4. **Close when finished.** Exit the drawer when the focused review is complete so the normal class view remains clear.

> **Check before continuing:** A page title, category, or still image can be incomplete. Confirm context before intervening.

### Work an assigned Coverage session

**Who can use this:** Staff member with a Coverage assignment

Claim only assigned students, use the coverage tool set, and release them when supervision ends.

1. **Open Available.** Review students made available to your supervision group and claim only the assignment you are taking.
2. **Confirm Claimed.** Wait for the claimed context to load before sending an action. The class owner and exact student bindings remain authoritative.
3. **Use coverage controls.** Send resources, manage allowed tabs and restrictions, message students, or apply the controls shown in Coverage. Tools not shown are not part of Coverage authority.
4. **Release cleanly.** Release the students when supervision ends so control returns to the correct class context.

## Wrap Up



### Wrap up and troubleshoot

**Who can use this:** Teacher or administrator

End the session, review outcomes, and know when an administrator must help.

1. **Check temporary controls.** Ending class clears Waypoints, Flight Paths, and other session controls automatically. Lift anything sooner only if students need it before the bell, then end class and wait for the session to close.
2. **Review the summary.** Check the session summary and any pending or unavailable outcomes that need later follow-up.
3. **Retry connection issues once.** Resync the class after a student reconnects. Do not repeatedly broadcast a command while the student remains unavailable.
4. **Escalate policy issues.** Ask an administrator for help with extension versions, school blocks, managed configuration, provider policy, setup keys, or official roster and schedule changes.

> **Flight note:** Include the student’s displayed status, the action, and the approximate time when reporting a problem. Do not send passwords or sign-in URLs.

# Student browsing history

ClassPilot's Student Data dialog has separate Summary and Browsing history tabs. Browsing history provides a student name/email search independent of current classes, online presence and aggregate reports. Select a student, then choose a school-local start and end date; use the same date in both fields for a single day. Teachers can find students they actually taught or supervised within the retention period, including students no longer in their current roster. Administrators can search school student records, including retained inactive records. No live classroom or Chromebook connection is required.

Student Data and the Student Detail drawer share the date-selected history view. It loads materialized top domains by day and a separate visit list, with 100 entries per page and a hard server cap of 500. Consecutive observations of the same page appear as one visit with a school-local start/end range and accumulated estimated time. The default list shows visits with page details; an option includes individual observations without page details. Changing dates, students or that option cancels stale requests and restarts pagination. Leaving the history view discards inactive history queries; failed reads hide previously loaded visits and summaries. The UI distinguishes empty history, expired dates, denied access, unavailable service and failed requests.

`GET /api/classpilot/students/browsing-history` accepts a name/email `search`, optional `grade` and `classId`, bounded `limit` and opaque `cursor`, returning student identities, pagination metadata and `filterOptions` without device IDs. Teachers receive active official classes they own or teach as primary/co-teacher; administrators receive active official classes in their school. Grade options include class grades and school-scoped roster grades, with additional school student grades for administrators. Each class lists its applicable grades so mixed-grade classes remain selectable. Current roster membership and grade/class filters intersect with the search before pagination; when both filters are selected, the grade must match the student or the selected class. Current assignments only narrow discovery. Teacher discovery still uses retained historical staff/roster and supervision authority; the lookup never grants access outside those intervals, and detailed endpoints reauthorize each selected date range and page.

Leave both filters on All to find formerly taught or supervised students outside current class assignments. Changing either filter clears the selected student and restarts pagination; Clear filters also resets the name/email search. Lookup cursors bind the search, grade and class to the actor, role and school, while existing unfiltered cursors remain compatible. Every page rechecks current filter scope in the same database snapshot as its options and students. Unavailable grades/classes return `HISTORY_FILTER_DENIED`; denied or pending lookups hide previous options and student/history data until a fresh authorized response. Filters use current school records rather than historical grade or class snapshots. Deploy the API before the frontend; no migration or extension release is required.

When an observation has no page title (including stored `Unknown` placeholders), the web app derives a display label from its recorded URL: for example, `Google search: photosynthesis`, `Google Docs document`, or the website hostname. Reported page titles take precedence. If neither a usable title nor a recognizable URL is available, it shows `Page details unavailable`. These labels also apply to recent activity, the browsing timeline and student tiles. They describe the recorded page, never infer typing, editing, video playback or a cause for missing data, and do not change stored observations or off-task classification.

`GET /api/classpilot/students/:studentId/browsing-history` accepts `startDate`, `endDate` (inclusive local dates, maximum 366 days), `limit`, `view=pages|all` and an opaque `cursor`. The API defaults to `all` for compatibility; the drawer requests `pages` by default. Omitted dates select today in the school's timezone. The response includes the selected view, timezone, retention cutoff, partial-expiry flag, scope, observation timestamps, page URL/title, educational classification, nullable stored content category, lock/camera indicators and estimated seconds. It contains no device IDs. `/browsing-history/domains` returns existing daily materializations for administrators and authorized class-session usage for teachers. Missing materializations are unavailable, not proof of no browsing; supervision-only summaries remain partial and the raw list remains authoritative for those observations.

The `pages` view filters before the page limit, so a run of hundreds of heartbeat observations without page details cannot consume result pages. An observation has page details when it contains a nonblank URL (including an internal browser URL) or a nonblank title other than the case-insensitive placeholders `Unknown`, `Page details unavailable`, `No page details` and `Browser observation`. Whitespace around titles is ignored. Meaningful title-only observations such as `Signing in` and `Assigned page` remain visible. The `all` view retains every authorized observation, including lock/camera evidence without page details. These are presentation filters: heartbeat storage, monitoring, retention and domain materializations remain unchanged, and missing page details are never filled with an earlier URL or treated as proof of an offline Chromebook.

The web client requests `grouping=visits` in either view. Omitted grouping (or `grouping=observations`) preserves the existing one-row-per-observation API contract. Visit responses add `startedAt`, `endedAt`, `observationCount` and `hasOffTaskObservation`; `timestamp` remains the newest observation for compatibility. The server groups the authorized raw stream before filtering missing-page rows or applying the page limit. A long stay therefore remains one complete entry even when it contains more observations than the page size.

Visits use the exact recorded URL, including its query and fragment; title changes on that URL do not create another visit. Without a URL, only identical meaningful titles can form a visit. Navigating to another page and returning creates separate visits. A missing-page observation, a device change, a gap over 60 seconds, a school-local midnight or an authorized-window boundary also breaks a visit. Missing-page observations remain individual entries in the `all` view and break visits even when hidden in the `pages` view. These boundaries are applied after retention/date/authority clipping, so grouping never recovers inaccessible observations.

Visit time is the sum of supported consecutive raw-observation intervals, using the same 60-second ceiling. In visit mode an intervening device switch cannot be skipped to find a later observation on the original device. The displayed end includes the last supported interval endpoint; final observations and gaps add no time. Classification and teacher intent are retained only when uniform across the visit; mixed values remain unknown. The off-task indicator records whether any observation was non-educational. Lock/camera indicators are true only when true throughout the visit. No claim of continuous focus, editing, playback or exact dwell time is made.

Deploy the API before the web client so visit grouping is supported when the drawer begins requesting it. This change requires no data migration or Chrome extension release and applies to already-retained history. Heartbeat collection and stored records remain unchanged.

Date boundaries use the canonical `schools.school_timezone`, the same clock as ClassPilot classes, dashboard and Clever sync. The legacy `settings.school_timezone` field does not override history dates; `settings.retention_hours` still supplies the retention policy.

Administrators may inspect all retained observations for the student. Teacher authority comes from completed frozen staff and roster snapshots on live teaching sessions and retained report authority, using the same helpers as Student Data. Current group assignment alone, an unattended scheduled report, or an administrator's Observe access cannot grant teacher history. The interval ends at the earliest actual/session/report deadline, scheduled end, twelve-hour limit or present time, and starts no earlier than roster capture. Delegated supervision is subtracted from class access; a teacher receives only their own supervision intervals, bounded by assignment/release/context times. Raw reads are clipped to the current school retention cutoff on every page.

Pagination seeks by `(timestamp DESC, id DESC)` with timestamp precision retained to six fractional digits. Visit pagination uses each complete visit's newest observation tuple, so visits are not split or repeated across pages. The cursor is bound to actor, role, school, student, date range, view and grouping and retains a fixed request horizon. Existing observation cursors remain usable in the `all` view; switching views or grouping requires a fresh first page. Each page rechecks authority and retention. Concurrent newer observations do not shift subsequent pages. Changing membership, retention or dates never makes a prior cursor an authority token.

Whole-session domain summaries are released only when an authorized interval covers the full materialized session/day slice. Late roster or staff capture, delegated gaps, clipped retention, timezone changes and unfinished session windows withhold that aggregate and mark the summary partial or unavailable. Aggregated domains cannot be made safe by merely trimming their displayed timestamps. A cursor also carries its original local date range so paging today's history continues safely across school midnight.

In the compatibility observation mode, estimated durations use the next raw observation for the same student and device inside the same authorized interval, only when observations are no more than 60 seconds apart. Visit mode additionally requires adjacent observations in the student's stream on the same local day, so intervening device switches and midnight interrupt attribution. Both modes include rows hidden by the `pages` view when determining durations, so missing-page intervals are never credited to the previous known page. Equal timestamps, isolated observations, gaps and the final observation contribute zero. They do not claim exact dwell time or fill unseen intervals. Category labels do not themselves make an observation off-task; historical null categories remain null.

## Query-plan evidence

The measurements below cover the original ungrouped `all` view. They do not measure the `pages` predicate or visit grouping. Whole-visit pagination must examine the selected student's retained authorized stream before limiting visits; it cannot use the old raw-row limit without fragmenting long visits. Long missing-detail streaks also require scanning past those rows within the authorized student/date range.

Read-only inspection of the local development table (115 rows) used a sequential scan with a small sort, 0.652 ms. That fixture was too small to justify a production index decision. `scripts/verify-browsing-history-plan.ts` creates connection-local synthetic temporary data (500,000 heartbeats, 100 students and multiple devices) and compares a representative deep timestamp/id cursor query. It never changes application records.

With the existing `(student_id, timestamp)` index, PostgreSQL scanned 102 rows, performed an incremental sort and returned 101 rows in 0.314 ms, reading 105 local blocks. A proposed `(school_id, student_id, timestamp DESC, id DESC)` index scanned 101 rows in 0.318 ms with the same block count. These local runs show no meaningful improvement from the proposed index, so this feature retains the existing indexes. The existing school/device/student/timestamp index supplies the per-row next-observation lookup. These are development query-plan observations, not production latency or scale guarantees.

The grouped query was separately measured with `EXPLAIN ANALYZE` against 100,000 synthetic retained observations for one student. The first and second 100-visit pages took approximately 1.42 and 1.44 seconds locally, retaining complete 300-observation visits. Window sorting used approximately 6,670 temporary 8 KiB blocks. Visit mode deliberately scans the authorized selected stream again on each page; broad retained ranges cost more than the compatibility raw-row seek. This local measurement is not a production latency or concurrency guarantee, and no index or schema change was introduced.

Run `node --env-file-if-exists=.env --import tsx scripts/verify-browsing-history-plan.ts` for the bounded synthetic comparison. The script refuses non-local database hosts. Unit tests in `tests/classpilot-browsing-history.test.ts` cover school-local DST dates, interval subtraction, cursor precision/scope and duration boundaries. The integration suite covers pagination, retention, cross-school denial and frozen teacher/supervision authorization.
